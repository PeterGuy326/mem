# mem-worker

Python AI Worker for the [mem](../README.md) project. Speaks gRPC to the Go
backend, runs per-mime **Processors** (Image / Text / PDF / Audio), and calls
pluggable **Providers** (Ollama / OpenAI / Idealab / Anthropic / …) for retrieval
embeddings and content understanding. It does not generate the Agent's answer.
The configured indexing LLM emits bounded description/tag suggestions for
text, PDF, and audio content. Suggestions remain subject to server-side human
review and are separate from Agent answer generation.

> **Status:** Image, Text, PDF and Audio processors are live. Ollama, OpenAI,
> Idealab, Anthropic and local CLIP adapters support the indexing capabilities listed
> below. The retired `Chat` RPC returns `UNIMPLEMENTED`; Agent answer generation
> is intentionally outside this Worker.

## Quickstart (local dev)

Requires Python ≥ 3.11 and [`uv`](https://docs.astral.sh/uv/).

```bash
cd worker
make install        # uv sync + install dev/test extras
make proto          # generate mem_worker/proto/processor_pb2*.py
make test           # pytest
make run            # python -m mem_worker.server  (binds 127.0.0.1:50051)
```

In private/auth-disabled mode the server **starts without Ollama**. Provider
construction is lazy: a processor only contacts a vendor inside `process()`.
Unsigned `HealthCheck` is liveness and answers `SERVING`; hosted readiness is a
separate signed exact-provider challenge.

### Running via Docker

```bash
docker build -t mem-worker:dev worker/
docker run --rm -p 127.0.0.1:50051:50051 \
  -e OLLAMA_BASE_URL=http://host.docker.internal:11434 \
  mem-worker:dev
```

### Hosted Worker trust boundary

SaaS must set `MEM_WORKER_AUTH_MODE=required`. memd signs every Process request
over the full gRPC method, exact scope, timestamp, 192-bit nonce, and
deterministic protobuf body. Worker verifies it before logging request data,
parsing options, fetching storage, or constructing a provider. The nonce is
claimed with Redis `SET NX EX` for ten minutes, so every replica must use the
same private Redis deployment; Redis failure is fail-closed.

Managed routes also require the fetched bytes to match the signed request
SHA-256 before provider egress. Every successful authenticated Process and
readiness response carries a request-nonce-bound HMAC over its deterministic
protobuf body. memd verifies that proof before persistence or accounting.
Unsigned HealthCheck remains liveness only. A signed readiness scope names the
exact V1/V2 managed embedding provider and proves the corresponding complete
binding without making a paid provider request.

A migration Worker may carry both the dedicated `IDEALAB_*` V2 binding and the
explicit `OPENAI_*` V1 binding. Set `MEM_OPENAI_MANAGED_BINDING=true` only for
that hosted V1 compatibility route. In every deployment, this flag reserves the
whole `openai:*` provider namespace for authenticated AI profiles: legacy
options and `MEM_DEFAULT_*` values cannot select any OpenAI model. Keep the flag
`false` for private BYOM. memd performs one signed readiness challenge per
enabled exact binding; arbitrary OpenAI-compatible specs are not promoted into
the managed allow-set.

In `saas` mode every non-empty `MEM_DEFAULT_*` value must name a local runtime
vendor (`ollama`, `clip`, `faster-whisper`, or `whisper`), and
`OLLAMA_BASE_URL` must be an absolute loopback HTTP(S) URL without credentials,
query, or fragment. Worker startup fails otherwise. Signed legacy/no-profile
requests selecting any non-local vendor—or encountering a non-loopback Ollama
binding after startup—are rejected before storage fetch and provider
construction. Remote provider egress is available only through an
authenticated, compiled AI profile.

HMAC authenticates and protects integrity but does not encrypt gRPC. Bind port
50051 only on a private, policy-restricted network and prefer TLS/mTLS.
Production replay Redis should use private networking or `rediss://`,
authentication, adequate capacity, and a no-eviction policy for live replay
keys. Never log or commit HMAC/provider keys.

Provider spec format is **`<vendor>:<model>`**, e.g.
`ollama:nomic-embed-text`, `clip:ViT-B-32`, `openai:gpt-4o-mini`.

The Ollama embedding adapter uses one batched `POST /api/embed` request with
`dimensions: 768` and `truncate: false`. It requires one exactly
768-dimensional numeric vector per input and fails closed otherwise; it never
truncates or pads vectors to imitate schema compatibility. For curated local
selection, artifact integrity checks, and explicit activation, see
[LOCAL_EMBEDDING_MODELS.md](../docs/LOCAL_EMBEDDING_MODELS.md).

For an OpenAI-compatible endpoint, leave `OPENAI_EMBEDDING_DIMENSIONS` unset
unless the selected endpoint explicitly supports the `dimensions` field. When
set, the Worker includes it in `POST /v1/embeddings` and rejects a response
whose vectors are not exactly that size. A selected workspace profile does not
use `MEM_DEFAULT_EMBEDDING`: it sends its fixed
`idealab:text-embedding-3-large` stage with `dimensions: 768` per request.
This is an embedding-only setting: it does not alter LLM or VLM requests, and
it does not pad or truncate vectors.

## gRPC contract (`proto/processor.proto`)

`Process` and `HealthCheck` are active. `Chat` remains only as a retired wire
compatibility slot and always returns gRPC `UNIMPLEMENTED`:

```proto
service ProcessorService {
  rpc Process(ProcessRequest) returns (ProcessResponse);
  rpc Chat(ChatRequest) returns (ChatResponse); // retired compatibility slot
  rpc HealthCheck(HealthCheckRequest) returns (HealthCheckResponse);
}
```

### `ProcessRequest`

| Field | Type | Notes |
| --- | --- | --- |
| `file_id` | string | mirrors `files.id` |
| `storage_uri` | string | `s3://bucket/key` (or `file:///…` in tests) |
| `mime` | string | magic-number detected by Go backend |
| `sha256` | string | hex digest |
| `user_id` | string | for per-user provider config (W2) |
| `name` | string | original filename hint |
| `options_json` | bytes | free-form JSON (per-request overrides) |

### `ProcessResponse`

Mirrors **SPEC §9.1 ProcessResult**:

| Field | Type | Notes |
| --- | --- | --- |
| `summary` | string | Optional extraction/indexing summary (may be empty; never an Agent answer) |
| `caption` | string | VLM caption (images) |
| `tags` | repeated string | auto tags |
| `entities` | repeated `Entity` | person / place / org / event |
| `embeddings` | `map<string, Embedding>` | keys: `text`, `visual`, `face` |
| `metadata_json` | bytes | JSON: EXIF, codec info, dim hints, errors |
| `processor` | string | which processor handled the file |
| `status` | enum | `OK / PARTIAL / FAILED / SKIPPED` |
| `error` | string | non-empty when `status == FAILED` |

An `Embedding` carries `provider`, `dim`, and one or more `EmbeddingRow`s
(`values`, `index`, `chunk_text`, `metadata_json`).

For a compiled managed profile, `metadata_json.managed_usage` is the closed
`mem.managed-stage-receipt/v1` contract. Its exact declared stage keys map only
to `not_invoked`, `succeeded`, or `indeterminate`; missing, extra, or unknown
values fail closed at the server settlement boundary. This receipt contains no
source text, endpoint, credential, vector, or raw upstream error.

Backend code generation lives in `server/internal/workerpb/` (Go).
Re-generate Python stubs with `make proto`.

## Processor inventory

| Processor | accepts | Status | Outputs |
| --- | --- | --- | --- |
| `ImageProcessor` | `image/*` | Live | EXIF/GPS, VLM caption, CLIP visual vector, optional face vectors |
| `TextProcessor` | `text/*` + JSON / YAML / common code MIMEs | Live | Chunked text embeddings plus lazily resolved, reviewable description/tag suggestions |
| `PDFProcessor` | `application/pdf` | Live | Text-layer extraction followed by the text pipeline; OCR is future work |
| `AudioProcessor` | `audio/*` | Live | ASR transcript followed by the text pipeline |

This inventory describes the Worker's legacy/unprofiled capabilities. A
compiled workspace profile restricts both MIME dispatch and enabled stages.
The current `local-fast-v2` and `idealab-quality-v2` revisions accept text and
`application/pdf`; only a PDF with a text layer produces downstream text
outputs. Scanned PDFs have no OCR path and release the unused stages. Both
profiles disable visual embedding, VLM, ASR, and rerank.

Image retrieval uses `open_clip` ViT-B/32 for both the indexed image vector and
the query text vector only on that legacy/unprofiled path. VLM captions are
stored as provenance-bearing metadata; caption-to-text indexing is a separate
roadmap item.

The production default (`clip:ViT-B-32`, OpenAI weights) is an English
baseline, not a claimed multilingual model. The real-model acceptance in
`tests/test_multilingual_visual_acceptance.py` must pass the fixed English and
Chinese queries before the default visual embedding space is changed. Changing
that model also requires a versioned reindex because vectors from different
CLIP checkpoints must not be mixed in one index.
