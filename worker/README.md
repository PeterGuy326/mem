# mem-worker

Python AI Worker for the [mem](../README.md) project. Speaks gRPC to the Go
backend, runs per-mime **Processors** (Image / Text / PDF / Audio), and calls
pluggable **Providers** (Ollama / OpenAI / Anthropic / …) for embeddings,
LLM, and VLM capabilities.

> **Status:** W1 skeleton. Image + Text processors are wired; PDF + Audio are
> stubs; OpenAI + Anthropic providers raise `NotImplementedError` (W2).
> See `SPEC.md §3 (F2/F8)` and `§9` for the authoritative contract.

## Quickstart (local dev)

Requires Python ≥ 3.11 and [`uv`](https://docs.astral.sh/uv/).

```bash
cd worker
make install        # uv sync + install dev/test extras
make proto          # generate mem_worker/proto/processor_pb2*.py
make test           # pytest
make run            # python -m mem_worker.server  (binds 0.0.0.0:50051)
```

The server **starts without Ollama**. Provider construction is lazy: a
processor only contacts Ollama (or any other vendor) inside `process()`, so
`HealthCheck` answers `SERVING` even when no model is available.

### Running via Docker

```bash
docker build -t mem-worker:dev worker/
docker run --rm -p 50051:50051 \
  -e OLLAMA_BASE_URL=http://host.docker.internal:11434 \
  mem-worker:dev
```

## gRPC contract (`proto/processor.proto`)

Two RPCs:

```proto
service ProcessorService {
  rpc Process(ProcessRequest) returns (ProcessResponse);
  rpc HealthCheck(HealthCheckRequest) returns (HealthCheckResponse);
}
```

### `ProcessRequest`

| Field | Type | Notes |
| --- | --- | --- |
| `file_id` | string | mirrors `files.id` |
| `storage_uri` | string | `s3://bucket/key` (or `file:///…` in tests) |
| `mime` | string | magic-number detected by Go backend |
| `sha256` | string | hex digest |
| `user_id` | string | for per-user provider config (W2) |
| `name` | string | original filename hint |
| `options_json` | bytes | free-form JSON (per-request overrides) |

### `ProcessResponse`

Mirrors **SPEC §9.1 ProcessResult**:

| Field | Type | Notes |
| --- | --- | --- |
| `summary` | string | LLM summary (may be empty) |
| `caption` | string | VLM caption (images) |
| `tags` | repeated string | auto tags |
| `entities` | repeated `Entity` | person / place / org / event |
| `embeddings` | `map<string, Embedding>` | keys: `text`, `visual`, `face` |
| `metadata_json` | bytes | JSON: EXIF, codec info, dim hints, errors |
| `processor` | string | which processor handled the file |
| `status` | enum | `OK / PARTIAL / FAILED / SKIPPED` |
| `error` | string | non-empty when `status == FAILED` |

An `Embedding` carries `provider`, `dim`, and one or more `EmbeddingRow`s
(`values`, `index`, `chunk_text`, `metadata_json`).

Backend code generation lives in `server/internal/workerpb/` (Go).
Re-generate Python stubs with `make proto`.

## Processor inventory (W1)

| Processor | accepts | Status | Outputs |
| --- | --- | --- | --- |
| `ImageProcessor` | `image/*` | Live | EXIF metadata, GPS entity, VLM caption, placeholder visual embedding |
| `TextProcessor` | `text/*` + JSON / YAML / common code MIMEs | Live | Chunked text embeddings, optional LLM summary |
| `PDFProcessor` | `application/pdf` | Stub | Returns `metadata.stub = true` (W2) |
| `AudioProcessor` | `audio/*` | Stub | Returns `metadata.stub = true` (W2) |

The visual embedding for images is currently produced by embedding the
**VLM caption** as text (via `MEM_DEFAULT_VISUAL_EMBEDDING`). This is a
deliberate W1 shortcut so we avoid pulling `torch` + CLIP into the base
image; W2 swaps in real `open_clip` ViT-B/32 (already an `[clip]` extra).

## Provider inventory (W1)

| Vendor | Embedding | LLM | VLM | Notes |
| --- | --- | --- | --- | --- |
| `ollama` | ✅ `embed_text` | ✅ `complete` + `stream` | ✅ `caption` + `vqa` | `embed_image` not supported; use CLIP in W2 |
| `openai` | stub | stub | stub | W2 |
| `anthropic` | n/a (no embedding API) | stub | stub | W2 |

## Open questions (need backend / SPEC clarification)

- Should the worker write to PostgreSQL directly, or always return results
  and let the backend handle persistence? SPEC §5 implies the latter; the
  task brief mentions "write back to PostgreSQL in W2". Defaulting to
  "worker returns, backend persists" until clarified.
- `options_json` payload schema: who owns it? Proposing a versioned JSON
  contract co-owned in `server/internal/workerpb/`.
- Default visual embedding dimensionality: Ollama text embed is 768 but
  schema in SPEC §6.1 reserves `vector(512)` for visual. Either pad/truncate
  in the worker or alter the schema once CLIP lands.
